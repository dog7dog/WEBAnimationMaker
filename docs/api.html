MOD API

window.AnimationApp が WEBAnimationMaker の公開APIです。MOD の main.js 内で const api = window.AnimationApp; として参照し、図形・ツール・コーディングブロック・UIなどを自由に追加できます。このページではMODのファイル構成から全APIリファレンスまでをまとめて説明します。

MODとは

MOD（モッド）は、WEBAnimationMaker 本体を書き換えずに機能を追加できる小さな拡張パッケージです。mod.json（メタデータ）と main.js（JavaScript）などをZIPにまとめてインストールすると、window.AnimationApp という共通APIを通じてエディタと連携します。

ZIPはブラウザの IndexedDB に保存され、次回以降の起動でも自動で読み込まれます。保存したプロジェクト（.mlc）に、MODが追加した図形タイプのデータも残ります。

カスタム図形

独自の描画ロジックを持つ図形タイプを追加できます。

カスタムツール

右パネルにツールボタンを追加し、マウス操作を乗っ取れます。

カスタムブラシ

ストローク描画を完全にコントロールするブラシを追加できます。

コーディングブロック

コーディングタブ（Blockly）に独自のトリガー・アクションブロックを追加できます。

カスタムUI

top / right / bottom / left / editor-top エリアにHTMLパネルを追加できます。

ファイルメニュー拡張

「ファイル」メニューに独自の書き出し・読み込み項目を追加できます。

Three.js統合

WebGLレンダラー（MOD側で用意）を2Dレイヤーと同じ管理下（表示/ロック/順序）に置けます。

ファイル構成

MODは ZIPファイル1つとして配布・インストールします。最小構成は次の3ファイルです。

my_mod.zip
├─ mod.json ← 必須。メタデータと読み込むファイルのリスト（manifest.json でも可）
├─ main.js ← 必須。エントリポイント
└─ style.css ← オプション
MOD IDに使えるのはアルファベット・数字・アンダースコアのみです。mod.json の id と registerMod() に渡す id は一致させてください。

mod.json

MODのメタデータと、読み込むファイルの一覧を書くマニフェストです。WEBAnimationMaker はインストール時にこのファイルを読んでMOD一覧に表示します。

{
  "id": "my_mod",
  "name": "My MOD",
  "version": "1.0.0",
  "description": "説明",
  "scripts": ["main.js"],
  "styles": []
}
フィールド型説明
idstringシステム内でユニークな識別子。registerMod() に渡す id と一致させる
namestringMOD一覧に表示される名前
versionstringセマンティックバージョン（例: 1.0.0）
levelnumberMOD一覧に表示されるだけの値。権限制御には使われていない
enabledboolean受け付けはするが現在は読まれない（古いサーバー配布時代の名残）
descriptionstringMOD一覧に表示される説明文
scriptsstring[]読み込むJSファイルのリスト（配列の順番どおりに実行される。省略時は main.js）
stylesstring[]読み込むCSSファイルのリスト（省略可）

main.js

MODの実処理を書くエントリポイントです。即時関数で囲んでグローバル変数の汚染を防ぎ、まず api.registerMod() を呼んでシステムに存在を知らせるのが基本形です。

(function () {
  const api = window.AnimationApp;
  if (!api) return;          // WEBAnimationMaker以外の環境対策

  api.registerMod({
    id: "my_mod",
    name: "My MOD",
    version: "1.0.0",
    description: "説明"
  });

  // ここから機能を追加する（registerShapeType / registerTool / registerActionBlock など）
})();
if (!api) return; を入れておくと、WEBAnimationMaker以外の環境で誤って読み込まれてもエラーになりません。

読み込みの仕組み

  1. mod.json（または manifest.json）と main.js などをZIPにまとめる。
  2. ツールバーの「MOD」→「MODをインストール」からZIPを選び、セキュリティ確認ダイアログで「インストール」を押す。
  3. ZIPの中身がブラウザの IndexedDB に保存され、scripts に書かれたJSファイルが実行される。内部で api.registerMod() が呼ばれた時点でそのMODがシステムに登録される。
  4. 次回以降の起動時も、IndexedDBに保存されたMODが自動で読み込まれる。

インストール済みMODは「MOD一覧」からアンインストールできます。MODが追加したブロック・図形・UIなどを個別に取り消す仕組みは無いため、アンインストール後は確認をはさんでページが自動的に再読み込みされます。

保存データへの影響

addShape() で追加した図形は、通常の図形と同じように .mlc プロジェクトファイルへ保存されます。

再読み込み時にそのMODがインストールされていないと、図形タイプが未登録のまま読み込まれます（データ自体は失われません）。保存データにはMODの識別子が記録されるため、必要なMODが不足している場合は警告が表示されます。

クイックスタート

実際に手を動かして最初のMODを作る手順です。完成例は下記「main.js」のコード例をそのまま使えます。

1

フォルダを作る

my_mod/ のようなフォルダを作成し、中に mod.json と main.js を用意します。

2

mod.json を書く

上記の最小構成をコピーし、id / name / description を自分のMODに合わせて書き換えます。

3

main.js に registerMod() を書く

即時関数の先頭で api.registerMod() を呼びます。これを呼ばないとMODがシステムに認識されません。

4

図形・ツールを登録する

registerShapeType() → registerTool() の順で呼ぶのが安全です。両方とも registerMod() の後に呼んでください。複数の図形タイプ・複数のツールを登録することもできます。

5

マウス操作を実装する

キャンバス要素にイベントリスナーを追加し、api.activeModTool?.id で自分のツールが選択中か確認してから処理します（下記「よくあるパターン」も参照）。

6

ZIPにまとめてインストールする

mod.json と main.js をZIPにまとめ、WEBAnimationMakerのツールバーの「MOD」→「MODをインストール」から選びます。セキュリティ確認ダイアログで「インストール」を押すと、MOD一覧に名前が出て右パネルにボタンが追加されます。

認識されない場合は、ブラウザの開発者ツールのコンソールを確認してください。mod.json のJSONが壊れている、または id/scripts が抜けていると、インストール時にエラーメッセージが表示されます。

基本

全てのAPI呼び出しの起点になる参照です。main.js の一番上で取得してください。WEBAnimationMaker以外の環境（例: テスト用の素のブラウザ）では undefined になるため、if (!api) return; で防御するのが安全です。

const api = window.AnimationApp;

登録系

registerMod(mod)

MODをシステムに登録します。main.jsの先頭で必ず呼んでください。これを呼ぶまでWEBAnimationMakerはこのスクリプトを「MOD」として認識しません。id・name・version・description はmod.jsonの内容と一致させておくと管理が楽になります。

api.registerMod({
  id: "my_mod",          // 必須。ユニークな識別子
  name: "My MOD",        // 表示名
  version: "1.0.0",
  description: "説明文"
});

registerTool(tool)

右パネルの「操作」エリアにツールボタンを追加します。ユーザーがボタンを押すとそのツールがアクティブになり、以後のキャンバス操作をMOD側で乗っ取れるようになります。

api.registerTool({
  id: "my_tool",         // 必須
  name: "マイツール",    // ボタンの title に表示
  icon: "◆"             // ボタン内 HTML（絵文字・HTMLどちらも可）
});

自分のツールが現在アクティブかどうかは、マウスイベントのハンドラ内で次のように確認します。アクティブでない場合は何もせず抜けるのが基本パターンです。

if (api.activeModTool?.id === "my_tool") { ... }

registerBrush(brush)

カスタムブラシを登録します。draw コールバック1つで、ストロークの描画を自分でコントロールできます。

api.registerBrush({
  id: "my_brush",
  name: "マイブラシ",
  icon: "🖌",
  // 必須: ストロークの全ポイントを毎フレーム受け取って描画する
  draw(ctx, points, opts) {
    ctx.save();
    ctx.strokeStyle = opts.color || "#fff";
    ctx.lineWidth = opts.sw || 4;
    ctx.beginPath();
    points.forEach((p, i) => i === 0 ? ctx.moveTo(p.x, p.y) : ctx.lineTo(p.x, p.y));
    ctx.stroke();
    ctx.restore();
  },
  // 任意: レイヤーパネルのサムネイル用SVGを返す
  toSVG(shape) { ... }
});

draw(ctx, points, opts) は、ストローク中は毎回全ポイント配列（{ x, y } の配列）を受け取って呼ばれます。開始・移動・終了で分かれたコールバックはありません。opts は、ストロークの描画中（プレビュー中）は { color, sw, opa, preview: true }、ストローク確定後の再描画時は保存された shape オブジェクトそのものが渡されます。

registerShapeType(type, renderer)

独自の図形タイプを登録します。図形1つぶんの「描画・当たり判定・移動・リサイズ・書き出し」をまとめて定義するAPIで、MODの中心となる機能です。draw だけが必須で、他は用途に応じて省略できます。

api.registerShapeType("my_shape", {
  // 必須: Canvas 2D で図形を描画する
  draw(ctx, s) {
    ctx.save();
    ctx.globalAlpha = (s.opa || 100) / 100;
    ctx.strokeStyle = s.color || "#fff";
    ctx.lineWidth = s.sw || 2;
    // ... 描画処理 ...
    ctx.restore();
  },

  // バウンディングボックスを返す
  getBounds(s) {
    return { x: s.x, y: s.y, w: s.w, h: s.h };
  },

  // 中心座標を返す
  getCenter(s) {
    return { x: s.x + s.w / 2, y: s.y + s.h / 2 };
  },

  // 移動
  move(s, dx, dy) {
    s.x += dx;
    s.y += dy;
  },

  // リサイズ（handle: 'se'|'sw'|'ne'|'nw'|'n'|'s'|'e'|'w'）
  resize(s, handle, start, nx, ny, nw, nh) {
    s.x = nx; s.y = ny;
    s.w = Math.max(4, nw);
    s.h = Math.max(4, nh);
  },

  // SVG 書き出し用
  toSVG(s) {
    return `<rect x="${s.x}" y="${s.y}" width="${s.w}" height="${s.h}"
              fill="none" stroke="${s.color}" stroke-width="${s.sw || 2}"/>`;
  }
});
コールバック必須役割
draw(ctx, s)必須Canvas 2Dコンテキストに図形を描画する。必ず ctx.save() / ctx.restore() で挟むこと
getBounds(s)任意選択枠・当たり判定に使うバウンディングボックスを返す
getCenter(s)任意回転の中心などに使う中心座標を返す
move(s, dx, dy)任意ドラッグ移動時に図形の座標を更新する
resize(s, handle, ...)任意選択枠のハンドルドラッグでサイズ変更する
toSVG(s)任意レイヤーパネルのサムネイル表示で使われるマークアップ文字列を返す
registerShapeType で追加した図形は、デザインタブの自前キャンバス上でのみ draw() によって描画されます。HTML書き出しやキャンバスタブのDOMプレビューはこの描画関数を参照しないため、そのままでは書き出したページ上に表示されません。書き出したページでも見た目を再現したい場合は、registerActionBlock 等でCSS/JSとして別途表現するか、書き出し後のHTMLに手を加える必要があります。

図形操作

addShape(shape)

キャンバスに新しい図形を追加します。アクティブなレイヤーに自動で配置され、レイヤーパネルにも表示されます。type には registerShapeType で登録したキー、もしくは組み込みの図形タイプを指定します。

api.addShape({
  type: "my_shape",      // registerShapeType で登録した type
  name: "マイ図形",      // レイヤーパネルの表示名
  x: 100, y: 100,
  w: 120, h: 80,
  // color / sw / opa / dash / fill / rot は省略時にエディタ設定値が使われる
});

Shapeの共通フィールド:

フィールド型説明
typestring図形タイプ
namestringレイヤーパネル表示名
colorstring色 (CSS color)
swnumber線の太さ
opanumber不透明度 (0–100)
dashstring破線パターン例: "5,3"
fillboolean塗りつぶし
rotnumber回転角度 (度)
hiddenboolean個別非表示
enginestring"canvas2d" (省略時) または "threejs"
layerIdstring配置レイヤー (省略時はアクティブレイヤー)
addShape で追加した図形は、通常の図形と同じようにコーディングタブの図形選択欄に並びます。動きを付けるのに特別な対応は不要です。

getSelected()

現在選択中の図形オブジェクトを返します。未選択時は null が返るため、必ずnullチェックしてから使ってください。

const s = api.getSelected();
if (s) console.log(s.type, s.x, s.y);

setSelectedPatch(patch)

選択中の図形のプロパティを部分的に更新し、左側のプロパティパネルの表示も自動的に同期します。カスタムUIのスライダーなどと組み合わせてよく使われます。

api.setSelectedPatch({ color: "#ff0000", sw: 4 });

redraw()

キャンバスの再描画を要求します。図形データを直接書き換えた後など、画面に即座に反映させたいときに呼びます。

api.redraw();

コーディング拡張

registerTriggerBlock(type, spec) / registerActionBlock(type, spec)

コーディングタブ（Blockly）に、独自のトリガー・アクションブロックを追加します。追加したブロックは既存のトリガー/アクション（クリック・スクロール・拡大・移動…）と同じ仕組みに間借りするので、ツールボックスへの表示・CSS/JS生成・警告チェックは自動でついてきます。MOD側で追加の登録は不要です。そのぶん trigger / action には既存の種別のどれかを指定する必要があります。まったく新しい効果をCSSレベルから足したい場合はこの2つの対象外です。

// アクションブロックの例: 傾ける(skew)を使った「グリッチ」ブロック
api.registerActionBlock("mod_glitch", {
  action: "skew",              // 必須。INTERACTION_ACTION_TYPES のいずれか
  category: "action",          // 省略可。"action"(既定) / "entrance" / "exit" / "loop"
  duration: 0.3,                // 省略可。時間欄の既定値（秒）
  parts: [{ el: "TARGET_EL" }, "にグリッチをかける"],
  tooltip: "一瞬だけガタつかせます",
  toParams: (block) => ({ dx: 20, dy: -10 })
});

// トリガーブロックの例: ダブルタップ(dblclickを流用)
api.registerTriggerBlock("mod_when_double_tap", {
  trigger: "dblclick",         // 必須。INTERACTION_TRIGGER_TYPES のいずれか
  toggleMode: "toggle",        // 必須。INTERACTION_TOGGLE_MODES のいずれか
  parts: [{ el: "TRIGGER_EL" }, "をダブルタップしたら"]
});

type はアプリ内で一意な識別子です。他のMODや組み込みブロックと衝突しないよう "mod_<あなたのMODのid>_..." のように名前空間を切ってください。重複していたり trigger/action が未対応の種別だと、コンソールに警告を出して登録を拒否します（戻り値は false）。

parts の書式は registerShapeType 等と同じブロック部品の指定です。{ el: "NAME" }（図形選択）・{ num: "NAME", def, min, max, step }（数値）・{ menu: "NAME", options }（選択肢）・{ text: "NAME", def }（文字入力）・文字列そのまま（ラベル）が使えます。

一覧値
INTERACTION_TRIGGER_TYPESclick dblclick hover press inview load key scroll scrollpage scrollany timer scrollview scrollprogress
INTERACTION_TOGGLE_MODESonce（1回きり）hold（押している/乗っている間）toggle（ON/OFF切り替え）scrub（スクロール位置に連動。scrollview/scrollprogress専用）
INTERACTION_ACTION_TYPESscale fade move slide rotate show hide skew flip stretch blur brightness grayscale saturate hue glow pulse spin float shake swing blink bounce path

toParams(block) は単一の { type: action, params } を、toActions(block) は複数のアクション [{ type, params }, ...] を組み立てます（どちらか一方が必須）。複数のアクションを1ブロックにまとめたい場合（例: 拡大しながらフェード）は toActions を使ってください。組み込みの「大きくしながら出す」ブロックが実例です。

UI拡張

registerUI(ui)

任意のパネルエリアにカスタムUIを追加します。簡単なHTML文字列を渡すだけでよく、より高度なDOM操作が必要な場合は render / onMount コールバックを使います。

api.registerUI({
  id: "my_ui",
  position: "right",     // "top" | "right" | "bottom" | "left" | "editor-top"
  title: "マイ設定",     // オプション
  html: `<button onclick="doSomething()">実行</button>`,

  // render / onMount で DOM を直接操作することもできる
  render(wrap, api) { ... },
  onMount(wrap, api) { ... }
});

position によって挿入先が変わります。ツールのオプションパネルには "right"、テキストエディタ画面に出したい場合は "editor-top" を使うのが一般的です。

registerFileMenuItem(item)

左上の「ファイル」メニューに独自の項目を追加します。書き出し・読み込みなど、ファイル操作系の機能をMODから提供したいときに使います。

api.registerFileMenuItem({
  id: "my_export",
  label: "カスタム書き出し",
  icon: "ti-download",   // Tabler Icons クラス名（省略可）
  onClick(api) {
    // 書き出し処理
  }
});

レイヤー

createLayer(options)

新しいレイヤーを作成してレイヤーパネルに追加します。作成したレイヤーは自動的にアクティブレイヤーになります。フォルダ型のレイヤーを作って、その中に子レイヤーをまとめることもできます。

const layer = api.createLayer({
  name: "WebGL Effects",    // 省略時 "New Layer"
  type: "normal",           // "normal"（省略時）または "folder"
  parentId: null,           // フォルダ内に入れる場合は親フォルダの id
  color: "#8b5cf6",         // レイヤーパネルのカラードット（省略時なし）
  visible: true,            // 省略時 true
  locked: false,            // 省略時 false
  opacity: 1,               // 0.0〜1.0（省略時 1）
  blendMode: "source-over"  // CSS globalCompositeOperation（省略時 "source-over"）
});
// → 作成したレイヤーオブジェクトを返す

典型的な使い方（addObjectと組み合わせる）:

const layer = api.createLayer({ name: "Particle Layer", color: "#ff9900" });

api.addObject({
  engine: "threejs",
  type: "particle",
  name: "パーティクル",
  layerId: layer.id       // 作成したレイヤーに配置
});

フォルダを作成してレイヤーを入れる:

const folder = api.createLayer({ name: "WebGL Group", type: "folder" });
const child  = api.createLayer({ name: "Effects",     parentId: folder.id });
type: "folder" のレイヤーは addShape / addObject の対象になりません。図形の追加先は getDrawableActiveLayerId() が自動的に子レイヤーへ振り分けます。

getLayers / isLayerVisible / isLayerLocked

現在のレイヤー構成を読み取るためのAPI群です。フォルダの表示/ロック状態が子レイヤーに継承されるかどうかも考慮した結果を返します。

// 全レイヤーを取得
const layers = api.getLayers();
// 例: [ { id, name, type, visible, locked, opacity, ... }, ... ]

// レイヤー状態の確認（フォルダの継承も考慮）
api.isLayerVisible("layer-1");  // → boolean
api.isLayerLocked("layer-1");   // → boolean

Three.js連携

addObject(obj) / removeObject(id) / updateObject(id, patch)

Three.jsなど、Canvas 2D以外のレンダリングエンジンを使うオブジェクトを shapes[] に登録するためのAPIです。登録することで、通常の図形と同じくレイヤーパネルでの表示/非表示やロックの対象になります。

const obj = api.addObject({
  type: "my_3d_object",
  engine: "threejs",          // 省略時 "threejs"
  name: "3Dオブジェクト",
  color: "#3B8AE6",
  sw: 1, opa: 100, dash: "0", fill: false
});

api.updateObject(obj.id, { name: "名前変更" });
api.removeObject(obj.id);

registerThreeRenderer(callbacks)

Three.jsレンダラー側がレイヤーの状態変化（表示切替・ロック・オブジェクトの個別非表示）を受け取るためのコールバックを登録します。addObject と組み合わせて、2DレイヤーパネルとWebGLシーンの状態を同期させるために使います。

api.registerThreeRenderer({
  onLayerVisibility(layerId, visible) { ... },
  onLayerLock(layerId, locked)        { ... },
  onObjectHidden(objectId, hidden, shape) { ... }
});

ユーティリティ

toast / setStatus / getBounds / getCenter / getSceneSnapshot

通知の表示や、図形の座標計算、シーン全体の情報取得など、細かい場面で使う補助的なAPIです。

api.toast("ti-check", "完了しました");   // トースト通知
api.setStatus("処理中...");              // ステータスバー

const bounds = api.getBounds(shape);    // → { x, y, w, h }
const center = api.getCenter(shape);    // → { x, y }

const snapshot = api.getSceneSnapshot();
// → { width, height, bg, fps, shapes[] }

getObjectsByLayer(layerId) / getObjectsByEngine(engine)

特定のレイヤーやエンジンに属する図形だけを絞り込んで取得します。Three.jsオブジェクトだけをまとめて処理したいときなどに便利です。

// 特定レイヤーの全オブジェクト（エンジン問わず）
api.getObjectsByLayer("layer-1");

// 特定エンジンの全オブジェクト
api.getObjectsByEngine("threejs");

getAsset(modId, path)

ZIP形式でインストールしたMODに同梱したアセット（画像など）の Blob URL を取得します。

const url = api.getAsset("my_mod", "assets/icon.png");
img.src = url;

MODの実行コード内（main.js）では、__assets["assets/icon.png"] で直接参照する方が簡単です。getAsset は他のMODのアセットを参照したい場合や、modId を動的に扱いたい場合に使います。

外部ライブラリ

libraries.load / declare / get / has / list

MODがThree.jsや物理演算エンジンなど、外部ライブラリをCDN等から読み込むための唯一の窓口です。テキストエディタやAI生成コードから外部URLへ直接<script>を差し込むことはできない仕組みになっており、読み込みは必ずこのapi.librariesを経由します。

// 宣言 + 即読み込み（Promiseで本体が返る）
const THREE = await api.libraries.load({
  id: "three",              // 省略時は name を使う
  name: "Three.js",
  type: "script",           // "script"(既定・UMDグローバル) | "module"(ES Module)
  url: "https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.min.js",
  globalName: "THREE"       // type: "script" のとき、読み込み後に window から取り出す変数名
});

// 「使えるようにだけしておく」宣言のみ（即読み込みしない）
api.libraries.declare("cannon", {
  name: "Cannon-es",
  type: "module",
  url: "https://cdn.jsdelivr.net/npm/cannon-es@0.20.0/dist/cannon-es.js"
});

// 登録済みか確認してから取得（初回のみ読み込み、以降はキャッシュを返す）
if (api.libraries.has("cannon")) {
  const CANNON = await api.libraries.get("cannon");
}

// 登録済み一覧
api.libraries.list();
// → [{ id, name, description, source, globalName }, ...]

loadに渡すopts.loadにカスタム関数を指定すると、UMD以外の特殊な読み込み処理（グローバル変数名が動的に決まる場合など）にも対応できます。mod.jsonのlibrariesフィールドで宣言した内容も、内部的にはこのdeclare()と同じ扱いになります。

よくあるパターン

実際のMOD開発でよく出てくる実装パターンを、コード例つきで紹介します。

プロパティパネルと連動する

選択中の図形のプロパティをカスタムUIから変更したいときは、setSelectedPatch をイベントリスナー内で呼びます。

document.getElementById("my-slider").addEventListener("input", function () {
  api.setSelectedPatch({ myProp: Number(this.value) });
});

カスタムUIを右パネルに追加する

registerUI の onMount でDOM要素を取得し、イベントを紐づけます。api.getSelected() と組み合わせて、選択中の図形の種類をチェックしてから更新するのが安全です。

api.registerUI({
  id: "my_ui",
  position: "right",
  title: "オプション",
  html: `<label>サイズ <input id="my-size" type="range" min="10" max="200" value="60"></label>`,
  onMount(wrap, api) {
    wrap.querySelector("#my-size").addEventListener("input", function () {
      const s = api.getSelected();
      if (s && s.type === "my_shape") api.setSelectedPatch({ r: Number(this.value) });
    });
  }
});

ファイルメニューに書き出し項目を追加する

getSceneSnapshot() でシーン全体を取得し、任意の形式に変換して書き出せます。

api.registerFileMenuItem({
  id: "my_export",
  label: "JSON で書き出し",
  icon: "ti-file-export",
  onClick(api) {
    const scene = api.getSceneSnapshot();
    const blob = new Blob([JSON.stringify(scene, null, 2)], { type: "application/json" });
    const url = URL.createObjectURL(blob);
    const a = document.createElement("a");
    a.href = url; a.download = "scene.json"; a.click();
    URL.revokeObjectURL(url);
    api.toast("ti-check", "書き出し完了");
  }
});

マウスでキャンバスに図形を配置する

カスタムツールを作る場合の定番パターンです。mousedown で開始点を記録し、mouseup で addShape を呼びます。他のツールと競合しないよう、e.stopImmediatePropagation() を必ず入れてください。

const cv = document.getElementById("cv");
let drawing = false, startX = 0, startY = 0;

function canvasPos(e) {
  const r = cv.getBoundingClientRect();
  return { x: e.clientX - r.left, y: e.clientY - r.top };
}

cv.addEventListener("mousedown", function (e) {
  if (api.activeModTool?.id !== "my_tool") return;
  e.preventDefault();
  e.stopImmediatePropagation();
  const p = canvasPos(e);
  startX = p.x; startY = p.y;
  drawing = true;
}, true);

cv.addEventListener("mouseup", function (e) {
  if (!drawing || api.activeModTool?.id !== "my_tool") return;
  e.preventDefault();
  e.stopImmediatePropagation();
  drawing = false;

  const p = canvasPos(e);
  const x = Math.min(startX, p.x);
  const y = Math.min(startY, p.y);
  const w = Math.max(10, Math.abs(p.x - startX));
  const h = Math.max(10, Math.abs(p.y - startY));

  api.addShape({ type: "my_shape", name: "My Shape", x, y, w, h });

  // ツールを解除して選択ツールに戻る
  api.activeModTool = null;
  document.querySelectorAll(".rp-btn[data-mod-tool]")
          .forEach(b => b.classList.remove("active"));
  if (window.setTool) window.setTool("select");
}, true);

コーディングタブに独自のブロックを追加する

既存のトリガー/アクション（クリック・スクロール・拡大・移動…）を組み合わせた新しいブロックを追加できます。ツールボックス表示・CSS/JS生成・警告チェックは自動でついてくるので、ブロックの見た目と組み合わせ方だけを書けば十分です。詳しくは registerTriggerBlock / registerActionBlock を参照してください。

追加した図形をコーディングタブで動かす

addShape で追加した図形は、通常の図形と同じようにコーディングタブの図形選択欄に並びます。動きを付けるのに特別な対応は不要です。

チェックリスト

MODを公開・共有する前に、次の項目を確認してください。

  • mod.json の id がフォルダ名と一致している
  • main.js が即時関数 (function(){ ... })() で囲まれている
  • api の存在確認（if (!api) return;）がある
  • registerMod() が最初に呼ばれている
  • draw() 内で ctx.save() / ctx.restore() をしている
  • getBounds() が正しいバウンディングボックスを返している
  • マウスイベントで e.preventDefault() + e.stopImmediatePropagation() をしている
